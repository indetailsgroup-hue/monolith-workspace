⚙️ MONOLITH Core Platform Components (6 Components)

แต่ละ component เป็น Platform-level — Client เพียง configure ผ่าน client config JSON ไม่ต้องแก้ไข code

1. Agent Framework
🔷 Platform-owned: Base Agent Architecture
  • › BaseAgent class — role, tools[], systemPrompt template, escalation policy
  • › Tool Registry — standard tools: send_line_message, update_project_status, query_kb, trigger_mcp_event, notify_pm, escalate_halt
  • › Prompt Engine — Jinja2 template rendering; injects client context at runtime
  • › Memory Layer — conversation context window (configurable turns)
  • › LLM Adapter — supports OpenAI GPT-4o, Anthropic Claude 3.5; switchable per client
🔶 Client configures: Agent Personas
  • › Agent names, roles, business domain context
  • › Domain-specific system prompt additions (ข้อมูลสินค้า, ราคา, เงื่อนไข)
  • › KPI thresholds (response time, accuracy targets)
  • › Enabled/disabled tools per agent
  • › Escalation recipients (PM phone, email)
2. MCP Event Layer
🔷 Platform-owned: Event Bus Infrastructure
  • › 12 standard MCP events: new_inquiry, brief_received, approval_request, project_created, first_response_4h, qc_checkpoint, halt_alert, bom_received, stock_alert, job_scheduled, job_complete, status_update
  • › Webhook handler /webhook/line — signature verify, event routing
  • › Event schema validation (JSON Schema)
  • › Retry / dead-letter queue
🔶 Client configures: Event Handlers
  • › Custom event payload fields (client-specific metadata)
  • › Event → Agent routing rules
  • › Webhook URL (client's server endpoint)
3. LINE Integration Engine
🔷 Platform-owned: LINE Messaging + LIFF Framework
  • › flex_builder.py — 7 Flex Message templates (Welcome/Acknowledgment/Approval Request/QC Alert/Job Scheduled/Job Complete/Status Update)
  • › Rich Menu Engine — stage-based switching (5 variants: DEFAULT/PROJECT/APPROVAL/INSTALL/COMPLETE)
  • › LIFF Framework — liff-status.ts + liff-approval.ts (TypeScript base apps)
  • › Keyword Auto-reply Engine — 6 rule templates
  • › notify_customer() + broadcast_to_customers() SDK functions
  • › LINE Notify DEPRECATED (March 2025) — Messaging API only
🔶 Client configures: LINE OA Channel
  • › LINE_CHANNEL_ACCESS_TOKEN, LINE_CHANNEL_SECRET
  • › 5 LIFF App IDs (LIFF_ID_STATUS / SCHEDULE / GALLERY / APPROVAL / REVIEW)
  • › Rich Menu image assets (brand-specific design)
  • › Flex Message color scheme + logo
  • › Keyword replies (brand voice, language)
4. Knowledge Base Engine
🔷 Platform-owned: KB Schema + Approval Workflow
  • › KB Schema v1.0.0 — schemaVersion, pfmeaRiskRows, raciMap, agentDefinitions, mcpEventSchema
  • › 4-stage approval workflow: Draft → Review → Approved → Deployed
  • › KB Query Engine — semantic search over domain content
  • › Import/Export API (JSON format)
  • › Version control + diff tracking
🔶 Client configures: Domain Content
  • › Product catalog, pricing, materials, specifications
  • › Business-specific PFMEA rows (failure modes unique to client's process)
  • › RACI map (client's team structure)
  • › FAQ content, policy documents
5. PFMEA Engine
🔷 Platform-owned: PFMEA Methodology Framework
  • › Risk Row Schema — 15 fields: id, processStep, potentialFailureMode, potentialEffectsOfFailure, severity, potentialCauses, occurrenceRating, currentControls, detectabilityRating, rpn, recommendedActions, responsibleParty, targetCompletionDate, actionsTaken, requiresHumanReview
  • › Severity scale 1–9 (universal); Critical threshold: Sev ≥ 8
  • › RPN calculation (Severity × Occurrence × Detectability)
  • › PFMEA Live Dashboard (filter/sort/status tracker)
  • › Test Case runner (TC-PFMEA format)
🔶 Client configures: PFMEA Content
  • › All pfmeaRiskRows (client's specific failure modes)
  • › Process steps mapping to agents
  • › Critical test cases (TC-{CLIENT}-NN format)
  • › Control owners (ชื่อคน / ทีม)
6. PWA Field App SDK
🔷 Platform-owned: Field App Framework
  • › 5-screen PWA base: GPS Check-In / Defect Capture / Site Checklist / Customer Sign-off / Job Summary
  • › Geolocation API (±50m accuracy check)
  • › Canvas Signature Pad
  • › Photo upload (base64) + preview (×3)
  • › Service Worker (Blob URL) — offline caching
  • › MCP event push on job_scheduled / job_complete
  • › LocalStorage for offline data persistence
🔶 Client configures: Checklist + Branding
  • › Checklist items (12 items per client's process)
  • › MCP server endpoint URL
  • › Accent color, logo
  • › PFMEA severity labels (ภาษาไทย / English)

🚀 MONOLITH Client Onboarding Process

ขั้นตอนการ onboard client ใหม่เข้า MONOLITH Platform — ใช้เวลา < 3 วัน (config-driven, no platform code changes)

  • 1
    Business Domain Analysis

    สัมภาษณ์ client: ธุรกิจคืออะไร, workflow หลักคืออะไร, team structure, customer touchpoints (LINE? Web? App?)

  • 2
    Agent Configuration

    กำหนด agents ที่ client ต้องการ (เลือกจาก Agent Framework), เขียน domain-specific system prompt additions, กำหนด KPI thresholds, เปิด/ปิด tools ที่ใช้

  • 3
    Knowledge Base Setup

    รวบรวม domain content: product catalog, pricing, FAQ, policies → import เข้า KB Schema v1.0.0 → approve via 4-stage workflow

  • 4
    PFMEA Risk Analysis

    workshop กับ client เพื่อระบุ process steps + failure modes ของธุรกิจ → สร้าง pfmeaRiskRows → classify Sev/Occurrence/Detectability → identify critical rows (Sev ≥ 8)

  • 5
    LINE OA Setup

    client สร้าง LINE Official Account + Provider → ลงทะเบียน 5 LIFF Apps → ออกแบบ Rich Menu images (brand-specific) → กำหนด keyword auto-replies → ส่ง credentials ให้ MONOLITH

  • 6
    Supabase Provisioning

    สร้าง Supabase project สำหรับ client → apply schema templates (projects + design_approvals tables) → กำหนด RLS policies → ส่ง anon key ให้ MONOLITH config

  • 7
    Client Config JSON Deploy

    สร้าง client_{id}.json ใน MONOLITH config store → deploy ผ่าน CI/CD → platform auto-registers client routing

  • 8
    Field App Configuration (ถ้า client มีทีม field)

    customize checklist items + MCP endpoint + branding → build PWA → deploy เป็น hosted URL หรือ Android APK

  • 9
    UAT — Evaluation Metrics

    รัน PFMEA test cases (TC-{CLIENT}-NN format) → ตรวจ agent response quality (4-level rubric) → Gate-1 scorecard ผ่าน → sign off

  • 10
    Go-Live

    switch LINE Webhook to production → activate Rich Menu → เปิด LIFF apps → brief ทีม client เรื่อง workflow → monitor MCP event logs 24h แรก
