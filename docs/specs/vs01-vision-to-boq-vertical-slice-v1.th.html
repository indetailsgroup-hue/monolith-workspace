ภาพรวมและวัตถุประสงค์

VS-01 คือ vertical slice แรก ที่พิสูจน์ความสามารถ end-to-end ของ Vision-to-BOQ pipeline ในระบบ MONOLITH Manufacturing OS


วัตถุประสงค์รายละเอียด
พิสูจน์ทางเทคนิคdrawing/photo → AI Evidence Draft → BOQ Draft ทำงานได้ใน sandbox ก่อน production
กำหนดขอบเขตPipeline ผลิต BOQ draft ที่ต้องมนุษย์ตรวจ ไม่ใช่ production truth
ยืนยัน Single Source of Truthก่อน AI คำนวณใดๆ ต้องมีค่า canonical เพียงชุดเดียว (§8)
สร้าง Prompt Contractทุก prompt มี version, structured output schema, confidence rules และ refusal rules
⚠️
VS-01 ไม่ ใช่ production release — เป็น pilot ที่ต้องผ่าน Acceptance Criteria ใน §13 ก่อนพิจารณา FR-18 หรือ production rollout

Confidence Rules

HIGH
Pass ไปยัง BOQ generation อัตโนมัติ
0.70–0.89
MEDIUM

0.50–0.69
LOW
Block BOQ + require human review
0.00–0.49
VERY LOW
Reject + return to user with reason

Human Review Workflow

Triggers ที่ต้องมี Human Review

Conditionทำอะไร
overall_confidence < 0.80Block auto-advance + ส่งไป HUMAN_REVIEW
Flag NEEDS_REVIEWFlag item นั้น + reviewer ต้องยืนยัน
Flag CONFLICTBlock item นั้น + ต้อง resolve ก่อน approve
Flag INFERREDFlag item นั้น + reviewer ต้อง acknowledge
Dimension นอก valid range §8Auto-flag + require review

Reviewer Actions

Actionผล
APPROVE itemItem status = reviewed
EDIT + APPROVE itemแก้ค่า + บันทึก edit_reason + reviewer_id
REJECT itemItem removed + ต้องใส่ rejection_reason
REJECT BOQ ทั้งหมดstatus = REJECTED + ต้องใส่ reason

Escalation Path

👤 Reviewer (Designer Agent context)
ไม่สามารถ resolve conflict
↓
🏭 Factory Agent Review
ยังไม่สามารถ resolve
↓
📋 PM Agent → Human PM
Escalate ไปยัง human PM
↓
❌ Reject BOQ + Return to Intake
ส่งกลับไปยัง customer intake phase
