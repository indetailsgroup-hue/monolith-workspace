# หน้าจอ Team Pulse — แบบและแผนดำเนินงาน

**วันที่:** 12 กันยายน 2026
**ขอบเขต:** หน้าจอ C-05 ที่อนุมัติแล้ว ทำใน checkout ผลิตภัณฑ์แยก โดยรักษา governance root และ nested product worktree เดิม
**เป้าหมาย:** ให้ผู้ดูแลจัดการรอบแบบสอบถาม และสมาชิกที่เข้าสู่ระบบตอบรอบที่เปิดอยู่ ผ่านหน้า Culture Metrics เดิม

## แบบที่เลือก

เพิ่มแท็บ Team Pulse ข้างแบบสำรวจและ Sentiment การแยกเป็นเส้นทางใหม่จะเพิ่มการนำทางซ้ำ ส่วนการแทรกในแบบสำรวจเดิมจะปะปนวงจรรอบแบบสอบถาม จึงใช้แท็บที่คงรูปแบบภาษาไทยและข้อจำกัดแพลนเดิม

TeamPulseBoard รับ orgId, plan, isAdmin และ userId ที่ไม่บังคับ ใช้แผงภายในที่เปลี่ยน key เมื่อเปลี่ยนองค์กร แพลน บทบาท หรือผู้ใช้ ซ่อนข้อมูลค้างตั้งแต่การแสดงครั้งแรกก่อน effect ล้างบริบท เริ่มด้วย setContext(orgId, plan), fetchSessions และ fetchSummary เฉพาะผู้ดูแล เมื่อออกจากหน้าเรียก setContext(null, null) ผลการทำงานเก่าจะไม่แสดงข้อความสำเร็จในบริบทใหม่

ผู้ดูแลกรอกชื่อและรหัสช่วงเวลาเพื่อสร้าง DRAFT เปิดรอบ DRAFT ปิดรอบ ACTIVE และดูสรุปหัวข้อของรอบที่เลือก สมาชิกเห็นเฉพาะ ACTIVE/CLOSED และตอบได้เฉพาะ ACTIVE โดยเลือกหนึ่งในห้าหัวข้อเดิม คะแนนจำนวนเต็ม 1–5 และความคิดเห็นที่ไม่บังคับ ไม่มีการเพิ่มตัวแก้ไข config หรือสิทธิ์อ่าน config

ใช้ผล boolean จาก store ตัดสินการยืนยัน: เมื่อ false เก็บค่าฟอร์มไว้ และล้างหลัง true เท่านั้น ใช้สถานะที่ฐานข้อมูลส่งกลับ โหลด sessions ใหม่เมื่อกดลองใหม่ และโหลดสรุปของผู้ดูแลหลังตอบหรือปิดรอบสำเร็จ แสดงสถานะกำลังทำงาน ผิดพลาด ว่าง และรอบที่ปิดแล้ว ตรวจชื่อ/ช่วงเวลาที่มีแต่ช่องว่างและคะแนนไม่ถูกต้องก่อนส่ง

รายการคำตอบไม่บันทึกรหัสผู้ใช้ แต่ยังต้องเข้าสู่ระบบและเป็นสมาชิกองค์กร ข้อความอิสระอาจระบุตัวบุคคลได้ จึงไม่รับประกันความนิรนามหรือหนึ่งคำตอบต่อคน คงพฤติกรรมสรุปเดิม: health status เป็น null เมื่อคำตอบน้อยกว่าสาม แต่ผู้ดูแลยังเห็นค่าเฉลี่ยและจำนวน

## หลักฐานการดำเนินงาน

การทดสอบเฉพาะส่วนผ่าน 137 กรณีในสี่ไฟล์: หน้าจอ 24 กรณี การโต้ตอบ Storybook แบบ portable หนึ่งกรณี dashboard 48 กรณี และ store 64 กรณี การโต้ตอบ Storybook ผ่านหลัง restoreAllMocks ด้วย TypeScript ของ source ทั้งหมดผ่าน ไฟล์หน้าจอใหม่สี่ไฟล์ผ่าน lint โดยไม่มีคำเตือน และการตรวจช่องว่างใน Git diff ผ่าน

การทดสอบเปลี่ยนบริบทครอบคลุมองค์กร แพลน บทบาท ผู้ใช้ และการเปลี่ยนบทบาทพร้อมผู้ใช้ กรณีหนึ่งส่งผลลัพธ์คำขอสรุปของผู้ดูแลผ่าน store จริงกลับมาหลังเปลี่ยนบทบาท และยืนยันว่าไม่เข้าทั้ง cache และหน้าจอ อีกกรณีเปลี่ยนเฉพาะผู้ใช้โดยองค์กร แพลน และบทบาทเดิม เพื่อตรวจว่าข้อความในฟอร์ม ผลสรุป และข้อความสำเร็จที่มาช้าถูกล้าง

การทบทวนแบบอ่านอย่างเดียวไม่พบจุดที่ขวางการรวมงาน และขอเพิ่มการทดสอบเปลี่ยนเฉพาะผู้ใช้ที่ระบุข้างต้น ตัวอย่างในเบราว์เซอร์เป็นข้อมูลสังเคราะห์ทั้งหมด การตรวจภาพบนบริการจริง CI และการ deploy เป็นขั้นตอนรับงานแยก

การตรวจเบราว์เซอร์ในเครื่องรอบแรกพบปัญหาความต่างสีเมื่อสืบทอดธีมมืดจากหน้าหลัก: การ์ดสีขาวรับข้อความสีขาว และช่องกรอกรับรูปแบบมืด จึงกำหนดพื้นหลังอ่อน ข้อความเข้ม และสีช่องกรอกของ Team Pulse โดยตรง พร้อมจำกัด color-scheme ของช่องกรอกไว้ในแผงนี้ root agent ตรวจภาพหน้าจอผู้ดูแลและสมาชิกซ้ำหลังแก้ไขแล้ว ยืนยันว่าป้ายข้อความ ช่องกรอก และการ์ดอ่านได้ชัดเจน

ตรวจเบราว์เซอร์ในเครื่องครบหกตัวอย่าง: ผู้ดูแล สมาชิก รอบปิด ข้อมูลว่าง ข้อจำกัดแพลน และการส่งคำตอบของสมาชิก หน้าสมาชิกไม่มีสรุปของผู้ดูแล รอบปิดไม่มีฟอร์มตอบ และแสดงข้อความข้อมูลว่าง/ข้อจำกัดแพลนถูกต้อง การส่งคำตอบแสดงข้อความสำเร็จ ล้างความคิดเห็น และยังไม่มีส่วนสรุปของผู้ดูแล การตรวจทั้งหมดใช้ข้อมูลสังเคราะห์และไม่ได้ส่งคำตอบจริง

**ขอบเขตการยืนยัน:** การทดสอบหน้าจอและ store ยืนยันพฤติกรรมฝั่งผู้ใช้ ส่วน RLS ฐานข้อมูล การทดสอบ migration ใหม่ CI และการรวมงานเป็นงานแยกของ root agent เอกสารนี้ไม่อ้างว่า deploy แล้วหรือพร้อมผลิตจริง
