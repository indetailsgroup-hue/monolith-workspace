4. WP1 — ระบบและการ deploy (วิศวกร 2.75–3.75 วัน)

งานวันเสร็จเมื่อ
1.1 ตรวจรายการ migration บน server เทียบกับ source และระบุผู้ถือ secret แต่ละตัว โดยไม่เปลี่ยนเลขไฟล์1–1.5มีรายการ migration และ secret owner ที่ตรงกับของจริง
1.2 แก้ Pages ทับกันแก้โค้ดแล้วใน PR #127 รอ merge และ deploy แล้วตรวจ URL 0.25/, /designer/, /docs/ เปิดได้ทั้งสาม
1.3 ตั้งค่า auth redirect, TLS และ env ของ pilot0.5login และ logout ได้จากเครื่องอื่น
1.4 ซ้อม backup และ restore ทั้ง DB และไฟล์ใน storage1–1.5มีบันทึกการกู้คืนที่สำเร็จ

จุดตัดสินใจหลัง WP1: ประเมินขอบเขตและงบของ WP2–WP4 ใหม่จากผลตรวจจริง

5. WP2 — องค์กร Daph และผู้ใช้ (วิศวกร 2–3 วัน)

งานวันเสร็จเมื่อ
2.1 สร้างองค์กร Daph และ site ด้วย seed ที่ผ่านการตรวจทาน (ยังไม่ทำหน้าสมัครเอง)0.5มี org ในฐานข้อมูล
2.2 เชิญผู้ใช้ 3–5 คนและกำหนดบทบาทใน org_members0.5ทุกคน login แล้วเห็นองค์กร Daph
2.3 ให้ tenantStore อ่านองค์กรจาก server และปิดการสร้างองค์กรใน browser0.5–1ล้าง browser แล้วองค์กรยังอยู่
2.4 (บังคับ) เทสต์อ่านและเขียนข้ามองค์กร0.5–1ผู้ใช้จากองค์กรอื่นถูกปฏิเสธทั้งการอ่านและการเขียน

6. WP3 — งานและใบเสนอราคาบน server (วิศวกร 6–9.5 วัน)

งานวันเสร็จเมื่อ
3.0 ตรวจ data model: ลูกค้า (customer_id), ผู้สร้าง (created_by), revision และการบันทึกหัวเอกสารกับรายการย่อยให้สำเร็จหรือล้มเหลวพร้อมกัน0.5–1มีข้อสรุปเป็นลายลักษณ์อักษรว่าต้องเพิ่ม schema หรือ RPC อะไร
3.1 jobStore บันทึกลง jobs และ job_panels1.5–2.5สร้างงานที่เครื่อง A แล้วเห็นที่เครื่อง B
3.2 realtime ใช้ client ที่ login แล้ว กรองตาม org_id และ migration เปิด realtime คืน (ต้องผ่าน 0.6 ก่อน)1อัปเดตข้ามเครื่องได้ และองค์กรอื่นไม่ได้รับ event
3.3 quotationStore บันทึกลง quotations และ quotation_lines พร้อม revision และผู้อนุมัติ1.5–2.5reload แล้วใบเสนอราคาและ revision ยังอยู่
3.4 เชื่อม project (Field app) กับงานและใบเสนอราคา0.5–1เปิดจาก project แล้วไปถึงงานและใบเสนอราคาได้
3.5 เขียน e2e/jobs-quotation.spec.ts ใหม่ให้ใช้ server แทน localStorage0.5–1ผ่านบน CI
3.6 ใช้ session ของผู้ใช้แทน anon key และแก้หรือลบ useCreateJobSubmit.ts0.5ทุกการเขียนลงฐานข้อมูลใช้ JWT ของผู้ใช้

7. WP4 — จากแบบถึง packet ภายใต้ NO_CUT (วิศวกร 2–3.5 วัน)

งานวันเสร็จเมื่อ
4.1 บันทึกแบบ 3D ผูกกับงานและ revision บน server1–1.5เปิดแบบเดิมได้จากเครื่องอื่น
4.2 เลือก packet path เดียว (packet เดิม หรือ server/src/packet/v2) แล้ว upload ผ่าน factory-api0.5–1มีใบรับจาก server พร้อม hash
4.3 (บังคับ) ทดสอบไฟล์ปกติ, ไฟล์ที่ต้องถูกปฏิเสธ และไฟล์ที่ถูกแก้ไข0.5–1ไฟล์ที่ถูกแก้ไขถูกปฏิเสธจริง ป้าย NO_CUT อย่างเดียวไม่นับว่าผ่าน

8. WP5 — เตรียมการฝั่งโรงงาน (พนักงาน Daph 5–9 วัน ทำคู่ขนานได้)

งานวันเสร็จเมื่อ
5.1 จับคู่รหัสวัสดุและอุปกรณ์เฉพาะที่บ้านทดลองใช้1.5–2.5ทุกชิ้นของบ้านทดลองมีรหัสในระบบ
5.2 อบรมผู้ใช้ 3–5 คน1–2แต่ละคนทำขั้นตอนของตัวเองได้
5.3 แบบฟอร์มบันทึกส่วนต่าง (ตามหัวข้อ 8 ของรายงาน v0.1)0.5พร้อมใช้
5.4 ซ้อม UAT 17 ขั้น (ตามหัวข้อ 9 ของรายงาน v0.1)1.5–3ทุกขั้นมีหลักฐาน และไม่นับขั้นที่ถูกข้ามว่าผ่าน
5.5 ซ้อมเทียบยอดการเงินกับบัญชีเดิม0.5–1ยอดตรงกัน หรืออธิบายส่วนต่างได้
