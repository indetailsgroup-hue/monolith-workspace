Maintainer procedure

  1. Repository Actions settings must already permit GitHub Actions to create pull requests. This change requests contents:write and pull-requests:write for the two workflows; it does not modify repository settings or branch protection. If the repository policy denies PR creation, the run fails and needs the owner to enable the setting. Do not substitute an old credential or bypass branch rules.
  2. The default GITHUB_TOKEN signs bot commits but does not trigger downstream push/pull_request CI. After the final bot update, a maintainer using their normal GitHub identity must close and reopen the generated PR. This creates a human-originated reopened event. Making a draft ready alone is insufficient because existing workflows do not subscribe to ready_for_review. If the bot updates again, repeat close/reopen for the new head.
  3. Verify all five required checks on that PR head and review the diff. Do not treat an absent check as success. Mark ready and obtain the owner's merge decision. Preserve [skip changelog] in the generated PR's merge/squash message.
  4. Different changelog PRs may conflict at the insertion marker. Re-run the original source workflow after earlier PRs merge, then repeat close/reopen and review; the latest main checkout retains previously merged entries.
  5. A successful generator now means generation and PR reconciliation succeeded, not that main or the live site changed. The existing Auto-Deploy SciSpace Site workflow may run on generator completion but checks out main, so it cannot publish the unmerged bot branch. Publishing new JSON still requires the generated PR to merge. Check actual hosting content separately.

Alternatives and limits

A GitHub App token could trigger CI automatically, but requires a separately authorized identity and secret setup; it is not introduced here. A custom REST/GraphQL PR publisher would duplicate branch, diff, signing and retry logic. The pinned existing action provides those operations with a small workflow change. Separate changelog PRs favor preserving every event over minimizing PR count.

No generated site content, Slack settings, SciSpace hosting, or branch protections are changed in this patch. sync-chapters.yml is a separate release workflow and remains outside this request. Actual PR-creation policy and bot signing must be confirmed in a real run after this workflow is active; local tests cannot establish them.
