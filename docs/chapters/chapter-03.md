# 3\. งานวิจัยและฐานทางวิชาการ

## 3\. งานวิจัยและฐานทางวิชาการ

### 3.1. PRISMA Systematic Literature Review

#### 3.1.1. วัตถุประสงค์การวิจัย

การทบทวนวรรณกรรมอย่างเป็นระบบนี้มีวัตถุประสงค์เพื่อระบุและสังเคราะห์หลักฐานในแปดมิติการวิจัยหลัก:

  1. **Sheet Nesting และ Bin Packing Optimization** : อัลกอริทึมการจัดวางแผ่นวัสดุและการบรรจุ
  2. **Model Context Protocol (MCP) Server Architectures** : สถาปัตยกรรมเซิร์ฟเวอร์ MCP
  3. **Digital Twin Integration** : การผสานระบบ Digital Twin
  4. **WebGPU-based 3D Configurators** : ระบบปรับแต่ง 3D ที่ใช้ WebGPU
  5. **Multi-tenant SaaS Patterns** : รูปแบบ SaaS แบบหลายผู้เช่า
  6. **AI-Driven Design Automation** : การออกแบบอัตโนมัติด้วย AI
  7. **Industry Standard File Formats** : รูปแบบไฟล์มาตรฐานอุตสาหกรรม
  8. **Budget-Constrained Design Validation** : การตรวจสอบการออกแบบภายใต้ข้อจำกัดงบประมาณ



#### 3.1.2. กลยุทธ์การค้นหา

การค้นหาครอบคลุมฐานข้อมูลหลายแหล่ง (SciSpace, Google Scholar) สำหรับบทความที่ตีพิมพ์ระหว่างปี 2018-2026 โดยใช้ทั้ง natural language queries และ Boolean operators ที่มุ่งเป้าไปที่ระบบการผลิตเฟอร์นิเจอร์ เทคโนโลยี Digital Twin, AI agents และอัลกอริทึมการเพิ่มประสิทธิภาพ [1]

#### 3.1.3. กระบวนการคัดกรอง

  * **Papers Identified** : 601 บทความ
  * **Duplicates Removed** : 42 บทความ
  * **Unique Papers for Screening** : 500 บทความ
  * **Abstract Screening** (threshold ≥4.0): 499 บทความถูกตัดออก
  * **Full-text Screening** (threshold ≥4.5): 1 บทความผ่านเกณฑ์
  * **Final Included** : 1 บทความ [1]



#### 3.1.4. เกณฑ์การคัดเลือก

**เกณฑ์รับเข้า (Inclusion Criteria):**

  1. เกี่ยวข้องกับอุตสาหกรรมเฟอร์นิเจอร์หรือตู้เก็บของโดยเฉพาะ
  2. นำเสนอสถาปัตยกรรมซอฟต์แวร์การผลิตขั้นสูง
  3. มีการนำอัลกอริทึมการเพิ่มประสิทธิภาพมาใช้
  4. ใช้เทคนิคการแสดงผลหรือการเชื่อมต่อระบบ
  5. มีตัวชี้วัดประสิทธิภาพเชิงปริมาณ



**เกณฑ์ตัดออก (Exclusion Criteria):**

  1. เกี่ยวข้องกับอุตสาหกรรมการผลิตทั่วไปที่ไม่ใช่เฟอร์นิเจอร์
  2. เป็นเพียงการทบทวนวรรณกรรมหรือบทความแนวคิดโดยไม่มีการนำไปใช้
  3. ไม่มีข้อมูลเชิงปริมาณหรือผลการทดสอบ



#### 3.1.5. ผลการคัดกรอง

ผลการคัดกรองที่เข้มงวดสะท้อนให้เห็นถึงความต้องการเฉพาะเจาะจงสำหรับอุตสาหกรรมเฟอร์นิเจอร์/ตู้เก็บของ ซึ่งทำให้ต้องตัดบทความที่เกี่ยวข้องกับการผลิตทั่วไปออกไป 450 บทความ [1] ช่องว่างในฐานหลักฐานนี้แสดงให้เห็นว่าจำเป็นต้องใช้วรรณกรรมการผลิตที่กว้างขึ้นและกลยุทธ์การปรับใช้ข้ามโดเมนเพื่อให้ข้อมูลสำหรับการออกแบบระบบที่ครอบคลุมทั้งแปดมิติการวิจัย

### 3.2. หลักฐานเชิงประจักษ์จากงานวิจัย

#### 3.2.1. บทความที่ผ่านการคัดเลือก

งานวิจัยของ Yang et al. (2024) เรื่อง "Enhancing Manufacturing Excellence with Digital-Twin-Enabled Operational Monitoring and Intelligent Scheduling" นำเสนอระบบ Digital Twin สำหรับอุตสาหกรรมแผ่นไม้แข็งแบบดั้งเดิมของจีน [2]

#### 3.2.2. ผลการปรับปรุงประสิทธิภาพ

งานวิจัยรายงานการเพิ่มประสิทธิภาพการจัดตารางการผลิต **8.93%** เมื่อเปรียบเทียบ Dynamic Selection Adaptive Genetic Algorithm (DSAGA) กับ traditional genetic algorithms (GAs) [2] การปรับปรุงนี้แสดงให้เห็นถึงศักยภาพของการผสาน AI-driven optimization เข้ากับ Digital Twin framework

#### 3.2.3. โดเมนการผลิต

  * **ภาคอุตสาหกรรม** : อุตสาหกรรมแผ่นไม้แข็งแบบดั้งเดิมของจีน
  * **ประเภทผลิตภัณฑ์** : แผ่นไม้แข็ง (solid-wood panels)
  * **กระบวนการผลิต** : สายการผลิตแผ่นไม้แข็ง
  * **ลักษณะสายการผลิต** : แบบดั้งเดิม ประสบปัญหาความไม่มีประสิทธิภาพและการนำเทคโนโลยีดิจิทัลมาใช้ช้า
  * **ความท้าทายทางธุรกิจ** : ความไม่มีประสิทธิภาพในการผลิต การนำเทคโนโลยีดิจิทัลมาใช้ช้า การจัดการของเสีย ความต้องการการติดตามแบบเรียลไทม์และการแก้ปัญหา และความโปร่งใส [2]



#### 3.2.4. ความเกี่ยวข้องกับระบบ Monolith

งานวิจัยนี้มีความเกี่ยวข้องโดยตรงกับระบบ Monolith ในหลายด้าน:
[code] 
    1. **การผสาน Digital Twin**: สถาปัตยกรรมแบบสี่ชั้นที่ใช้ฐานข้อมูล MySQL และโปรโตคอล OPC UA สามารถนำมาใช้โดยตรงสำหรับการผลิตเฟอร์นิเจอร์แบบโมดูลาร์
    2. **AI Agents/การเพิ่มประสิทธิภาพการจัดตาราง**: การผสาน DSAGA เข้ากับชั้น virtual layer เพื่อเพิ่มประสิทธิภาพ (8.93% ดีกว่า traditional GAs) มีความเกี่ยวข้องกับ AI agents ที่เพิ่มประสิทธิภาพตารางการผลิตเฟอร์นิเจอร์แบบโมดูลาร์
    3. **การติดตามแบบเรียลไทม์และการจำลองกระบวนการ**: ระบบอำนวยความสะดวกในการติดตามแบบเรียลไทม์ การจำลองกระบวนการ และการแก้ปัญหาทันที ซึ่งเป็นสิ่งสำคัญสำหรับ Manufacturing OS ในการให้ความโปร่งใสและเพิ่มการแสดงผลข้อมูลสำหรับการผลิตเฟอร์นิเจอร์แบบโมดูลาร์
    4. **รูปแบบสถาปัตยกรรม**: ระบบ Digital Twin แบบหลายชั้น (physical, transport, virtual, application) ให้รูปแบบสถาปัตยกรรมสำหรับการเชื่อมโยงการผลิตทางกายภาพและการติดตามดิจิทัลใน Manufacturing OS \[2\]
    
[/code]

### 3.3. สถาปัตยกรรม Digital Twin ที่ได้รับการพิสูจน์แล้ว

#### 3.3.1. สถาปัตยกรรมแบบสี่ชั้น

งานวิจัยนำเสนอสถาปัตยกรรม Digital Twin ที่ประกอบด้วยสี่ชั้นหลัก [2]:

**1\. Physical Layer (ชั้นกายภาพ)**
[code] 
    - เชื่อมต่อกับอุปกรณ์และเครื่องจักรในสายการผลิตจริง
    - รวบรวมข้อมูลจากเซ็นเซอร์และอุปกรณ์ IoT
    - ควบคุมการทำงานของเครื่องจักร
    
[/code]

**2\. Transport Layer (ชั้นการสื่อสาร)**
[code] 
      - ใช้โปรโตคอล OPC UA (Open Platform Communications Unified Architecture)
      - รับประกันการสื่อสารที่เชื่อถือได้และปลอดภัยระหว่างชั้นกายภาพและชั้นเสมือน
      - รองรับการส่งข้อมูลแบบเรียลไทม์
    
[/code]

**3\. Virtual Layer (ชั้นเสมือน)**
[code] 
        - จัดเก็บข้อมูลในฐานข้อมูล MySQL
        - รันอัลกอริทึม DSAGA สำหรับการเพิ่มประสิทธิภาพการจัดตาราง
        - จำลองกระบวนการผลิตและทำนายผลลัพธ์
    
[/code]

**4\. Application Layer (ชั้นแอปพลิเคชัน)**
[code] 
        - ให้อินเทอร์เฟซผู้ใช้สำหรับการติดตามและควบคุม
        - แสดงผลข้อมูลและการวิเคราะห์
        - รองรับการตัดสินใจและการแก้ปัญหา
    
[/code]

#### 3.3.2. เทคโนโลยีหลัก
[code] 
        - **ฐานข้อมูล**: MySQL สำหรับการจัดเก็บข้อมูลและการจัดการ
        - **โปรโตคอลการสื่อสาร**: OPC UA สำหรับการเชื่อมต่อที่เป็นมาตรฐานอุตสาหกรรม
        - **อัลกอริทึม**: Dynamic Selection Adaptive Genetic Algorithm (DSAGA)
        - **อัลกอริทึมเปรียบเทียบ**: Traditional Genetic Algorithms (GAs) \[2\]
    
[/code]

#### 3.3.3. ข้อได้เปรียบของสถาปัตยกรรมนี้
[code] 
        1. **การแยกส่วนที่ชัดเจน**: แต่ละชั้นมีหน้าที่ที่ชัดเจน ทำให้ง่ายต่อการพัฒนาและบำรุงรักษา
        2. **มาตรฐานอุตสาหกรรม**: ใช้ OPC UA ซึ่งเป็นมาตรฐานที่ยอมรับในอุตสาหกรรม
        3. **ความยืดหยุ่น**: สามารถเปลี่ยนหรือปรับปรุงแต่ละชั้นได้โดยไม่กระทบชั้นอื่น
        4. **ความสามารถในการขยาย**: รองรับการเพิ่มอุปกรณ์และฟังก์ชันใหม่ได้ง่าย
        5. **การพิสูจน์แล้ว**: มีหลักฐานเชิงประจักษ์ว่าสามารถเพิ่มประสิทธิภาพได้จริง (8.93%) \[2\]
    
[/code]

#### 3.3.4. การนำไปใช้กับระบบ Monolith

สถาปัตยกรรมนี้สามารถนำมาปรับใช้กับระบบ Monolith ได้โดย:
[code] 
        1. **Physical Layer**: เชื่อมต่อกับเครื่องจักร CNC, เครื่องตัด และอุปกรณ์ในโรงงานผลิตเฟอร์นิเจอร์
        2. **Transport Layer**: ใช้ OPC UA หรือโปรโตคอลสมัยใหม่เช่น MQTT สำหรับ IoT
        3. **Virtual Layer**: ขยายให้รวม MCP server, AI agents และระบบเพิ่มประสิทธิภาพต่างๆ
        4. **Application Layer**: พัฒนาเป็น web-based interface ที่ใช้ WebGPU สำหรับการแสดงผล 3D
    
[/code]
