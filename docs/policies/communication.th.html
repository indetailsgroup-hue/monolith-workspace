นโยบายการสื่อสาร MONOLITH

มติผู้ใช้: 30 กันยายน 2026 ฉบับอังกฤษ: Communication policy

ข้อตกลง

MONOLITH ใช้ LINE สำหรับการสื่อสารของทีมและการแจ้งเตือนถึงคน ยกเลิก Slack จาก integration ที่ใช้งาน ตัวอย่าง สคริปต์สร้างเอกสาร และคำแนะนำ ห้ามนำกลับมาจากบทสนทนาเก่า template หรือ roadmap

การส่งอัตโนมัติต้องใช้ LINE OA ผ่าน Messaging API ที่ได้รับอนุญาต การเลือกช่องทางไม่ได้พิสูจน์ว่าเชื่อมต่อสำเร็จ ต้องตรวจผู้รับ สิทธิ์ การส่ง และการจัดการความล้มเหลวก่อนอ้างว่าเปิดใช้ ห้ามสร้างตัวส่งใหม่หรือส่งข้อความทดสอบเพียงเพื่อแทน workflow ที่ยกเลิก ให้ประสานตามขอบเขตงาน LINE OA ที่มีอยู่

การถอดและป้องกันการกลับมา

การแก้ไขนี้ลบ workflow แจ้ง deploy และรายการอ้างอิงใน CI, test และ README ปรับ roadmap ตัวอย่าง alert เอกสาร onboarding และสคริปต์สร้างเอกสารให้ใช้ช่องทางที่ตกลง และระบุส่วนที่ยังไม่ทำว่าเป็นข้อเสนอ การแก้ migration SQL เปลี่ยนเฉพาะ comment ไม่เปลี่ยนพฤติกรรมฐานข้อมูลและไม่รัน migration

required check เดิมชื่อ Validate Site Files รันตัวตรวจนโยบายการสื่อสารทุก PR เข้า main ตรวจทั้งไฟล์ที่ติดตามด้วย Git และไฟล์ใหม่ที่ไม่ถูก ignore ครอบคลุมชื่อ workflow, dependency, source, template, Markdown, HTML และ JSON ที่สร้างขึ้น รายงานเฉพาะตำแหน่งไฟล์ ไม่แสดงค่า secret ที่ตรงกับการค้นหา

รันตรวจในเครื่อง:

python tools/check_communication_policy.py
python -m unittest discover -s tests/docs -v
python -m scripts.docs.site_data

หลักฐานที่เก็บไว้

บทสนทนาที่ export และบันทึก audit/implementation ที่ลงวันที่แล้วคงไว้เป็นหลักฐานประวัติ ไม่ถือเป็นการอนุญาตให้เลือก integration ปัจจุบัน คำว่า “slack” ในงานวิศวกรรมหมายถึงระยะเผื่อทางกลหรือการคำนวณ ไม่ใช่ช่องทางสื่อสาร

หลักฐานเหล่านี้ ตัวนโยบาย และตัวอย่างด้านลบใน test มีข้อยกเว้นเฉพาะไฟล์ใน tools/communication_policy_exceptions.json ทุกข้อระบุเหตุผลและ SHA-256 หลังปรับ CRLF เป็น LF การยกเว้นผูกกับชื่อและเนื้อหาของแต่ละไฟล์: ไฟล์ใหม่ ตัวอย่างที่คัดลอกไป หรือไฟล์ยกเว้นที่ถูกแก้และยังมีชื่อช่องทางที่เลิกใช้ จะไม่ผ่าน ต้องตรวจความเปลี่ยนแปลงก่อนอัปเดตข้อยกเว้น ห้ามเพิ่ม integration ที่ใช้งานจริงลงในรายการยกเว้น

ขอบเขตการนำขึ้นใช้งาน

การถอดในเครื่องจะมีผลบน GitHub หลัง sign, push, review และ merge การแก้ไขนี้ไม่ได้เปิดหรืออ้างว่ามีการแจ้ง deploy ผ่าน LINE ประวัติ workflow บน remote และประวัติ Git ยังคงเป็นหลักฐานเดิม ส่วน secret ระดับ repository หรือ environment ถ้ามี ต้องตรวจด้วยสิทธิ์ที่เหมาะสมโดยดูเฉพาะชื่อ ไม่จำเป็นต้องอ่านค่า และตัวตรวจนี้ไม่อ่าน credential
